# tgllmbro

Telegram-помощник на aiogram, OpenAI-совместимые API и SQLite. В личных сообщениях
бот отвечает только владельцу. В группах он собирает поток сообщений в батчи,
подтягивает краткосрочный контекст, карточки участников, архив и примеры живой
речи, а затем через tool calls выбирает ответы, реакции и мемы.

## Запуск

Нужен Python 3.11 или новее. Для голосовых ответов нужен `ffmpeg` в `PATH`.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполни в `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `GEMINI_API_KEY` — ключ Gemini API из Google AI Studio.
- `ANYMODEL_API_KEY` — ключ AnyModel; если задан, модель из `ANYMODEL_MODEL`
  становится основным текстовым провайдером;
- `OPENROUTER_API_KEY` — необязательный резервный ключ OpenRouter. Оставь пустым,
  чтобы полностью отключить OpenRouter;
- `OWNER_TELEGRAM_ID` — числовой Telegram ID владельца личного диалога.

Затем запусти:

```powershell
python main.py
```

Если задан `ANYMODEL_API_KEY`, текст и tool calling сначала идут через
`ag/gemini-3-flash`. С пустым `OPENROUTER_API_KEY` при ошибке запрос сразу
переходит в прямой Google API. Для ручного перехода на Sonnet достаточно
заменить `ANYMODEL_MODEL` на `ag/claude-sonnet-4-6` и перезапустить бота.
Google API также используется для `gemini-embedding-2` и
`gemini-3.8-flash-lite-tts`;
модели и голос можно поменять без правки кода через `.env`. База создастся
автоматически в `data/bot.sqlite3`.

Основной runtime-лог сохраняется в `logs/bot-runtime.log`. В нём фиксируются
провайдер, модель, тип запроса, успешность и задержка без текста переписки.
Для OpenAI-совместимых провайдеров там же записываются реальные input/output
token counts.
При достижении 5 МБ файл ротируется; сохраняются пять предыдущих файлов.

## Что уже есть

- `/start` и `/help` — краткая справка;
- `/reset` — полное удаление истории текущего пользователя;
- закрытая личка только для владельца;
- debounce группового потока: 1.2 секунды тишины, 0.2 секунды для прямого
  обращения и максимум 8 секунд на батч;
- социальный шлюз: без обращения модель получает 1–3 случайных шанса в час в
  зависимости от активности чата; самостоятельная реплика требует score не
  ниже 0.92 и имеет cooldown 10 минут, фоновая реакция — cooldown 3 минуты;
- самостоятельная реплика может быть адресным reply или естественной фразой в
  общий поток; после ответа до трёх сообщений того же собеседника в течение
  75 секунд считаются кандидатами на продолжение. Чужие сообщения и ответы
  другим людям не подхватываются. «Понял, спасибо» закрывает продолжение;
- короткие фоновые батчи сохраняются без LLM-вызова, а в API передаются только
  инструменты, применимые к текущему сообщению;
- очередь с несколькими workers вместо API-запроса на каждое сообщение;
- три слоя памяти: последние 15 событий, отдельные карточки участников и весь
  архив чата с SQLite FTS5;
- долговременная SQLite-память с гибридным поиском: Gemini embeddings, FTS5 и
  оценка важности;
- безопасное точечное обновление карточки пользователя: один явный факт за
  tool call, без перезаписи остальных данных;
- прямой многошаговый tool loop без агентов-координаторов: модель сама вызывает
  поиск, получает результат и затем выбирает Telegram-действие;
- полнотекстовый поиск по архиву чата, безопасное чтение публичных ссылок и
  чтение вложений (текст, код, PDF, изображения, аудио и небольшие видео);
- актуальный веб-поиск: сначала Google Search grounding, при исчерпанной квоте
  автоматически DuckDuckGo Lite; найденные ссылки возвращаются модели;
- tool calls для reply, реакций, мемов, звуков, стикеров, TTS, MLBB-базы,
  памяти и молчания;
- `/addmeme описание` ответом на картинку добавляет Telegram `file_id` и
  embedding в локальную базу мемов;
- `/addsticker описание` ответом на стикер добавляет его в семантическую базу;
- `/addsound описание` ответом на войс или аудиофайл добавляет звуковой мем;
- `/addmlbb заголовок | факт | ссылка` добавляет проверенную запись в локальную
  MLBB-базу; перед игровым ответом агент ищет в ней версионные данные;
- каналы поддерживаются, если бот видит посты и имеет право публиковать;
- typing-индикатор и разбиение длинных ответов;
- ключи только в `.env`, который исключён из Git.

## Диалог и медиа

Личка и группы используют один обработчик с инструментами и характером из
`bot/persona.py`. В контексте есть авторы, роли и текст цитаты: собственные
реплики бота отделены от чужих. Примеры показывают смену темы, мнение,
исправление ошибки и молчание; ругань разрешена, но шутка не обязательна.
Из старой базы стиля берутся максимум два совпавших примера через FTS,
без отдельного запроса embeddings на каждую реплику.

На обращение с вложением или цитатой вложения бот сначала читает медиа.
Успешные описания кешируются отдельно для каждого чата и используются в
следующих репликах. Это описание для модели, а не загрузка картинки в каждый
запрос. Лимит файла — 4 МБ; максимум два автоматически читаемых вложения на
батч. Остальные доступны через `read_attachment`.

- Фото и обычные стикеры описывает vision-модель AnyModel.
- GIF, WEBM-стикеры, видео и кружки: до четырёх кадров первых 12 секунд,
  без звуковой дорожки. TGS-стикеры — только статичное превью, если оно есть.
- Голосовые: Google; при ошибке/таймауте — локальный faster-whisper, CPU int8,
  первые 90 секунд. `LOCAL_STT_MODEL=base`; веса сохраняются в `data/models`.
  Первая загрузка требует интернет и около 150 МБ. Расшифровка может ошибаться.
- Озвучка: Google TTS; при ошибке/таймауте — онлайн Edge TTS с голосом
  `FALLBACK_TTS_VOICE=ru-RU-DmitryNeural`. FFmpeg преобразует звук в OGG/Opus.
  Если обе озвучки не сработали, готовый ответ отправляется текстом.

Мемы, стикеры и звуки не появляются сами. Ответь на нужный файл командой
`/addmeme`, `/addsticker` или `/addsound`: описание/расшифровка будет получено
автоматически. Можно дописать своё описание после команды — особенно полезно
объяснить локальную шутку или момент, когда звук уместен. Добавляет только
владелец. При пустой базе модель не получает инструменты отправки из неё.
Мемобаза даёт подходящие реакции; естественная речь зависит прежде всего от
контекста, модели и выбора, когда вообще отвечать.

Проверка без запуска Telegram: `python -m unittest discover -s tests -v`.
Она использует временную БД и заглушки отправки. Живые образцы проверки
25.10.2026 сохранены локально в `logs/dialogue-check/`.

## Загрузка мемов и примеров речи

Импорт возобновляемый: уже добавленные пути и дубликаты с одинаковым SHA-256
пропускаются. Картинки описывает основная vision-модель AnyModel, затем описание
индексируется. Если квота Google embeddings исчерпана, запись всё равно
добавится и будет находиться через FTS; после восстановления квоты её можно
переиндексировать для полного семантического поиска. Сначала разумно прогнать
небольшой лимит, потому что описание картинок расходует API-запросы.

```powershell
python scripts/import_content.py D:\memes --mode memes --limit 20
python scripts/import_content.py D:\style.txt --mode style
python scripts/import_content.py D:\TelegramExport\result.json --mode style --author soybob
python scripts/import_content.py data\mlbb_seed.md --mode knowledge
```

В `.txt` и `.md` каждый абзац, отделённый пустой строкой, считается отдельным
примером ответа. Если нужен пример с контекстом, формат такой:

```text
что было сегодня в чате?
>>>
да классический день в дурке: один устроил срач, остальные искали токены
```

Для Telegram JSON `--author` определяет, чьи реплики считать эталоном; флаг
можно передать несколько раз. Картинки остаются файлами на диске, а SQLite
хранит их абсолютные пути, AI-описания и embeddings, поэтому на VPS эти файлы
тоже должны лежать по сохранённым путям.

Звуки, добавленные из Telegram, хранятся как `file_id`, поэтому бот отправляет
их напрямую и не зависит от `@sound`. Inline-боты вроде `@pic` вызываются
пользователем, а не другим ботом; для картинок используется собственная база
`/addmeme`. Стартовый MLBB-набор помечен официальной версией 2.2.16 — после
нового патча базу нужно обновить, а не выдавать старую мету за текущую.

Основной диалог, выбор действий и изменение карточек идут на Flash. Слабую
дешёвую модель безопасно подключать позже только для фонового чернового
сжатия, но не для tool calls, которые меняют данные.

Hermes Agent не встраивается как Python-зависимость: его актуальный runtime
требует отдельную управляемую установку на Python 3.14, а штатный Telegram
gateway использует другой фреймворк. Здесь сохранён aiogram и реализована нужная
Hermes-модель исполнения — единый прямой tool loop без промежуточных агентов.

Для сбора всего потока группы нужно отключить Privacy Mode: BotFather →
`/setprivacy` → выбрать бота → `Disable`. Иначе Telegram присылает боту только
команды, упоминания и ответы на его сообщения, поэтому полноценный batching
невозможен.
